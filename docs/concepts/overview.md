# Обзор концептов

**можно.** построен вокруг нескольких ключевых понятий. Понимание их взаимодействия поможет эффективно управлять фичами.

### Флаг

Именованная точка переключения в вашем коде. Поддерживает два типа:

- **RELEASE** — стандартный фиче-флаг для постепенной раскатки новой функциональности
- **KILLSWITCH** — аварийный выключатель для мгновенного отключения функциональности

Подробнее: [Флаги](/concepts/flags)

### Стратегия

Определяет, **как** флаг применяется на конкретном окружении. Стратегия включает:

- **Состояние** — включён/выключен флаг на этом окружении
- **Контекст** — набор правил (constraints), которым должен соответствовать пользователь
- **Сегменты** — переиспользуемые группы пользователей
- **Процентный роллаут** — процент пользователей, для которых флаг активирован

Подробнее: [Стратегии](/concepts/strategies)

### Сегмент

Переиспользуемая **группа пользователей**, объединённая общими признаками через контексты. Вместо того чтобы дублировать правила таргетинга на каждом флаге, вы создаёте сегмент один раз и ссылаетесь на него.

Примеры сегментов:

- Пользователи из России
- Premium-подписчики
- Мобильные устройства на iOS
- Бета-тестеры

Подробнее: [Сегменты](/concepts/segments)

### Контекст

Набор атрибутов, которые ваше приложение передаёт в SDK при оценке флага. Атрибуты могут быть любыми: `userId`, `country`, `plan`, `device`, `email` и т.д.

Оценка флага происходит **локально** в SDK без сетевого запроса к серверу. Правила загружаются фоновым процессом и кешируются.

```java
MozhnoContext ctx = MozhnoContext.builder()
    .userId("user-123")
    .addProperty("country", "RU")
    .addProperty("plan", "premium")
    .build();

boolean enabled = client.isEnabled("new-checkout", ctx);
```

```typescript
const enabled = client.isEnabled('new-checkout', {
  userId: 'user-123',
  country: 'RU',
  plan: 'premium',
});
```

### Окружение

Логически изолированный контекст для флагов:

- **dev** — локальная разработка, эксперименты
- **staging** — предпродакшен, интеграционное тестирование
- **production** — боевое окружение

Каждое окружение имеет **собственные настройки стратегий** и **собственные API-ключи**. Флаг, включённый в dev, может быть выключен в production.

Подробнее: [Окружения](/concepts/environments)

### API-ключ

Ключ доступа SDK к серверу **можно.**. Каждый API-ключ:

- Привязан к конкретному окружению
- Имеет гранулярные права (SERVER — чтение/запись, FRONTEND — только чтение)
- Может быть отозван в любой момент

### Аудит

Все изменения конфигурации флагов записываются в аудит-лог:

- Кто изменил (администратор или API-клиент)
- Что изменилось (старое и новое значение)
- Когда произошло изменение
- В каком окружении

Аудит-лог доступен через веб-панель и REST API.

## Модульная архитектура

**можно.** разделён на четыре Gradle-модуля:

| Модуль | Назначение |
|--------|------------|
| `mozhno-spi` | Service Provider Interface — точки расширения для плагинов |
| `mozhno-core` | Бизнес-логика: оценка флагов, сегменты, стратегии, JdbcTemplate |
| `mozhno-web-api` | REST-контроллеры, DTO, Spring Security, JWT |
| `mozhno-app` | Точка входа Spring Boot, статические ресурсы, Flyway-миграции |

Сервер — Spring Boot 4.0 / JDK 25. Веб-интерфейс — React 19 SPA (Vite, Tailwind CSS 4, Radix UI). SDK загружают правила флагов один раз и принимают решение локально.
