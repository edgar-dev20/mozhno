# Флаги

Флаг — это именованная точка переключения в коде. **можно.** поддерживает два типа флагов, процентный роллаут, правила на атрибутах (контекстах) и сегменты.

## Типы флагов

### RELEASE

Стандартный фиче-флаг для постепенной раскатки новой функциональности. Включается для целевой аудитории через правила таргетинга и процентный роллаут.

```java
if (client.isEnabled("new-checkout")) {
    // новая логика оформления заказа
} else {
    // старая логика
}
```

```typescript
if (await client.isEnabled('new-checkout')) {
  // новая логика оформления заказа
} else {
  // старая логика
}
```

### KILLSWITCH

Аварийный выключатель для мгновенного отключения функциональности. Обычно активен (включён) для всех, а выключается при инцидентах. Всегда проверяется как `isEnabled()` — если вернул `false`, значит функциональность заблокирована.

```java
if (!client.isEnabled("kill-payment-gw")) {
    throw new ServiceUnavailableException();
}
```

## Правила таргетинга (контексты)

Правила на атрибутах позволяют включать флаг для конкретных пользователей или групп на основе контекста оценки.

### Операторы сравнения

| Оператор | Описание | Пример |
|----------|----------|--------|
| `in` | Точное совпадение со значением из списка | `country` in `[RU, BY, KZ]` |
| `not_in` | Не входит в список | `country` not_in `[US, CA]` |
| `eq` | Равенство (числовое — для `contextType: number`) | `age` eq `18` |
| `ne` | Неравенство | `plan` ne `free` |
| `gt` | Больше | `version` gt `2.0` |
| `gte` | Больше или равно | `age` gte `21` |
| `lt` | Меньше | `priority` lt `5` |
| `lte` | Меньше или равно | `retries` lte `3` |
| `contains` | Содержит подстроку | `email` contains `@company.com` |

### Типы контекста

| Тип (`contextType`) | Поведение | Пример |
|---------------------|-----------|--------|
| `string` (по умолчанию) | Строковое сравнение | `country` in `[RU, KZ]` |
| `number` | Числовое сравнение | `age` gte `18` |
| `time` | Сравнение ISO8601 дат | `eventDate` gt `2026-01-01T00:00:00Z` |
| `semver` | Семантическое версионирование | `appVersion` gte `2.1.0` |

### Пример правила

```json
{
  "field": "country",
  "operator": "in",
  "values": ["RU", "BY", "KZ"]
}
```

Правила группируются в **контексты** (context definitions). Все правила внутри контекста должны выполниться (логическое И).

## Сегменты

Сегмент — переиспользуемая группа пользователей со своим набором правил. Сегменты ссылаются на контексты и могут быть назначены стратегии флага.

Примеры сегментов:
- Пользователи из EU
- Premium-подписчики
- Бета-тестеры

Стратегия может ссылаться на несколько сегментов — достаточно совпадения с любым (логическое ИЛИ).

## Процентный роллаут

Процентный роллаут распределяет флаг между пользователями детерминированно — на основе MurmurHash3 от `flagKey + userId` (или `sessionId`). Один и тот же пользователь всегда попадает в одну и ту же группу.

| Процент | Поведение |
|---------|-----------|
| 0% | Флаг выключен для всех |
| 25% | Флаг включён для ~25% пользователей |
| 50% | Флаг включён для ~50% пользователей |
| 100% | Флаг включён для всех |

## Логика оценки флага

При вызове `isEnabled()` SDK выполняет оценку в следующем порядке:

1. **Флаг выключен?** → вернуть `false`
2. **Нет стратегии?** → вернуть `true`
3. **Проверка контекста:** все правила контекста должны выполниться (И)
4. **Проверка сегментов:** хотя бы один сегмент должен совпасть (ИЛИ)
5. **Если есть и контекст, и сегменты:** достаточно совпадения одного из них (ИЛИ)
6. **Процентный роллаут:** MurmurHash3 хеш от `flagKey + userId`, сравнение с процентом
7. **Ничего не совпало** → вернуть `false`

## Жизненный цикл флага

Флаг имеет два состояния:

| Состояние | Описание |
|-----------|----------|
| **Активен** | Флаг создан, доступен для оценки SDK |
| **В архиве** | Флаг заархивирован. SDK не получают его конфигурацию |

Дополнительно, для каждого окружения флаг может быть **включён** (`enabled: true`) или **выключен** (`enabled: false`).

## Лучшие практики

1. **Именование** — используйте осмысленные ключи в kebab-case: `new-checkout`, `ai-search-enabled`, `dark-mode-rollout`
2. **Удаляйте устаревшие флаги** — флаг, полностью включённый больше месяца, должен быть удалён
3. **Не вкладывайте флаги** — избегайте `if (flagA && flagB)` — это усложняет отладку
4. **Документируйте флаги** — в веб-панели есть поле описания, заполняйте его
5. **Мониторьте** — отслеживайте, какие флаги активны и как долго
